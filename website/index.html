Why Vaultly

How it works

Three layers, one trust boundary

Humans hold the control plane. Agents hold nothing.

architecture
# Layer 1 — Human control plane
master password → OS keychain → unlock
add · rotate · delete · rekey · policy
# Layer 2 — Agent broker
MCP / CLI → policy engine → scrubber
metadata + status only · no values
# Layer 3 — Approved execution
deploy · exec (allowlisted) · sync
scoped creds · never in build logs

Humans unlock. Agents request. Vaultly decides.

Vaultly sits between your agents and your secrets. The master password lives in your OS keychain. Agents talk to a policy engine that can grant operations but never values.

  • Master password never leaves the credential store
  • Secret values scrubbed from all subprocess output
  • Hash-chained audit trail for every operation
  • Policy file is owner-managed (mode 0600)
  • Expired credentials block subprocess execution
  • Encrypted local profile with production semantics
