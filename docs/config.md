# Vaultly Configuration

This document describes every configurable surface of Vaultly: the master
`config.json`, the environment variables, the per-vault encrypted files, the
TUI theme, and the validation rules enforced on names, keys, and values.

All field and variable names below are grounded in the actual Rust source
(`rust/crates/vaultly-core/src/crypto.rs`, `rust/crates/vaultly-core/src/vault.rs`,
`rust/crates/vaultly-core/src/policy.rs`, `rust/crates/vaultly/src/tui.rs`).

---

## Layout

```
~/.vaultly/                      # aka $VAULTLY_DIR (see below)
├── config.json          # master config — KDF params + verifier (no secrets)
├── audit.log            # structured JSON audit trail (hash-chained, 1 MiB cap)
├── theme.toml           # optional TUI color theme override (see below)
└── vaults/
    ├── cf-personal.vault     # one encrypted AES-256-GCM file per vault
    └── <name>.vault          # (name sanitized, see Validation)
```

Everything is written with strict `0600`/`0700` permissions.

## `config.json` — master config

Single JSON object written to `<dir>/config.json`. Created by `vaultly init`.
Opened/parsed by `VaultStore::load_config` and serialized by
`VaultStore::save_config`. **It never contains secret values** — only the
crypto parameters and a verifier.

| Field | Type | Set by | Description |
|-------|------|--------|-------------|
| `version` | `u32` | `vaultly init` | Config format version, currently `1`. Rejected at load if unsupported. |
| `salt` | `string` (hex) | `vaultly init` | 32 random bytes (64 hex chars) generated by `generate_salt()`. Shared by every vault under this install and fed to PBKDF2 with the master password. |
| `verifier` | object | `vaultly init` | `EncryptedPayload` (fields `iv`, `authTag`, `ciphertext`) — an AES-256-GCM encryption of the derived 256-bit key used to verify the master password on unlock. |
| `createdAt` | `string` (ISO-8601) | `vaultly init` | UTC timestamp of initialization, `chrono::Utc::now().to_rfc3339_opts(SecondsFormat::Millis, true)`. |
| `backup` | object \| absent | `vaultly backup -u <url>` | `BackupMeta` with `workerUrl` and `lastBackupAt`. Absent (omitted) until the first backup. |
| `autoLockMinutes` | integer \| absent | `vaultly init` | Idle auto-lock timeout in minutes, from `VAULTLY_AUTO_LOCK_MINUTES`. Absent (omitted) until set. Applied by the engine's `op()` gate on unlock from `config.json`. |

Example shape: see [`docs/example-config.json`](example-config.json).

> The policy engine (`AgentPolicy`) is **not** persisted in `config.json`. Allowed
> operations and max-ops-per-minute are applied in-memory per agent from
> compile-time defaults, overrideable at runtime via `VAULTLY_MAX_OPS_PER_MINUTE`,
> or per-agent via a JSON policy file referenced by `VAULTLY_AGENT_POLICY`.

## Per-vault file: `vaults/<name>.vault`

Each vault is its own file (`VaultFile`). Same AES-256-GCM as the verifier;
the inner plaintext is JSON of secret key/value pairs.

| Field | Description |
|-------|-------------|
| `version` | Vault file format version, currently `2` (v1 bare-string files remain readable and are migrated on the next write; `validate_vault_file` accepts `1` or `2`). |
| `iv` | 16-byte random IV (hex). |
| `authTag` | 16-byte GCM auth tag (hex). |
| `data` | Encrypted inner JSON (hex). In v2 the inner JSON is a map of **per-secret objects**: `{"<key>": {"value", "createdAt", "updatedAt", "expiresAt"?}}` (`SecretEntry`). v1 stores bare string values; both decode cleanly. |
| `updatedAt` | ISO-8601 UTC timestamp of the last write to this vault. |

> Each vault carries its own `updatedAt` — there is no top-level one in
> `config.json`.

## Environment variables

| Variable | Default | Effect |
|----------|---------|--------|
| `VAULTLY_DIR` | `~/.vaultly` | Overrides the vault data directory (`VaultStore::default_dir`). Also used by the TUI to locate `theme.toml`. |
| `VAULTLY_ALLOW_KEYCHAIN` | unset | Set to `1` when intentionally using macOS Keychain with a custom `VAULTLY_DIR`; otherwise custom stores remain isolated from the real Keychain. |
| `VAULTLY_MAX_OPS_PER_MINUTE` | `60` | Positive integer overriding the agent rate limit (`PolicyEngine::default_max_ops`). Values ≤ 0 fall back to the default. Constant: `DEFAULT_MAX_OPS_PER_MINUTE = 60`. |
| `VAULTLY_AGENT_MODE` | `1` | Compatibility switch: `=0` disables default agent mode; `=1` explicitly enables it. |
| `VAULTLY_HUMAN_MODE` | unset | `=1` enables human-only commands for one invocation, overriding agent mode. |
| `VAULTLY_MASTER_PASSWORD` | unset | Supplies the master password for non-interactive unlock. CLI/MCP/server flows also support the macOS Keychain; agent mode never falls back to a prompt. |
| `VAULTLY_THEME` | unset | Path to a custom TUI theme file; overrides the default `<dir>/theme.toml`. |
| `VAULTLY_QUIET` | unset | `=1` suppresses non-essential output (also honors `NO_COLOR`). |
| `VAULTLY_AUTO_LOCK_MINUTES` | unset | Positive integer (minutes) idle auto-lock timeout. Read at `init` and persisted to `config.json` `autoLockMinutes`; the engine auto-locks after that much idle time since the last operation. |
| `VAULTLY_SERVER_TOKEN` | unset | Bearer token for the `vaultly serve` REST server (alternative to `--token`, preferred so it never appears in `ps`). |
| `VAULTLY_AGENT_POLICY` | unset | Path to a per-agent policy JSON file loaded by the policy engine; overrides compile-time defaults for allowed operations and limits. |

## TUI theme

The interactive TUI reads a palette from a TOML-like file — the path given by
`VAULTLY_THEME`, else `<dir>/theme.toml` — see `Theme::load_theme`/`parse_color`
in `rust/crates/vaultly/src/tui.rs`.

Keys mirror the `Theme` struct fields (`#[derive(Clone, Copy)]`), each a color
name (`black`, `red`, `green`, `yellow`, `blue`, `magenta`/`purple`, `cyan`,
`white`, `gray`/`grey`/`darkgray`) or a 6-digit hex like `#22d3ee`:

| Key | Default | Purpose |
|-----|---------|---------|
| `fg` | `white` | Default foreground |
| `accent` | `cyan` | Titles, borders |
| `success` | `green` | Success messages |
| `error` | `red` | Error messages |
| `warn` | `yellow` | Warnings, focused borders |
| `dim` | `darkgray` | Dimmed text |
| `selected_bg` | `cyan` | Selected list-row background |
| `selected_fg` | `black` | Selected list-row foreground |

Lines that are empty, start with `#` or `[`, or fail to parse are skipped.

```toml
# ~/.vaultly/theme.toml
accent = "#22d3ee"
warn   = "yellow"
```

## Validation rules

Enforced by `VaultStore::{sanitize_name, validate_key_name, validate_value}` in
`rust/crates/vaultly-core/src/vault.rs`. Rejects fail the operation with an
error (nothing is written).

### Vault names — `sanitize_name`

- Any **control character** in `name` → error `InvalidVaultName` (rejected
  outright, never silently renamed).
- Every remaining character is mapped to `-` unless it is ASCII alphanumeric,
  `-`, or `_`.
- Empty result or a result of just `"-"` → error.
- Examples: `"my vault"` → `"my-vault"`; `..` → `"--"` (no traversal); newline
  in a name → rejected.

### Secret key names — `validate_key_name`

- A key containing any **control character** → error `InvalidKeyName`.
  (Keys become map keys surfaced to agents as names, so nothing can inject into
  output/JSON.)

### Secret values — `validate_value`

- Value byte length > `MAX_SECRET_VALUE_LENGTH` (256 KiB, i.e.
  `256 * 1024`) → error `ValueTooLarge`.

| Constant | Value | Source |
|----------|-------|--------|
| `PBKDF2_ITERATIONS` | `600_000` | `crypto.rs` (OWASP 2023 PBKDF2-SHA256) |
| `KEY_LENGTH` / salt length | 32 bytes (256-bit key) | `crypto.rs` |
| `IV_LENGTH` | 16 bytes | `crypto.rs` |
| `AUTH_TAG_LENGTH` | 16 bytes | `crypto.rs` |
| `MAX_SECRET_VALUE_LENGTH` | 256 KiB | `vault.rs` |
| `AUDIT_MAX_BYTES` | 1 MiB (before rotation) | `vault.rs` |
| `DEFAULT_MAX_OPS_PER_MINUTE` | 60 | `policy.rs` |
